# GPay Market → внешние площадки: план интеграции

Источник: официальная документация Partner API v1  
Swagger: https://gpay.market/partner-api/index.html  
OpenAPI: https://gpay.market/partner-api/swagger/v1/swagger.json

## Вывод

Технически GPay Market можно использовать как источник каталога и поставщика:

1. Получать каталог через `POST /partner-api/products/list`.
2. Читать карточку через `POST /partner-api/products/get`.
3. Получать актуальную партнерскую цену через `POST /partner-api/pricing/product` либо `/pricing/appsub`.
4. Публиковать или обновлять товары на GGsel и других площадках через их API.
5. Рассчитывать цену продажи с наценкой, конвертацией валюты и резервом на комиссию.
6. После покупки на внешней площадке проверять цену и баланс, создавать и подтверждать заказ в GPay.
7. Передавать покупателю результат доставки в формате, разрешенном API и правилами площадки.

Это API-интеграция, а не парсинг HTML.

## Данные каталога

`POST /partner-api/products/list` поддерживает:

- `page`;
- `pageSize` — максимум 100;
- `productType`;
- `search`.

В товаре доступны:

- `id`;
- `appId`, `subId`;
- `name`;
- `imageUrl`;
- `productType` (`SteamGift` или `Keys`);
- `currentPartnerPrice` в USD;
- `isAvailable`;
- `gameId`;
- `isDlc`;
- `warningMessage`;
- `discountPercent`, `discountEndTime`;
- `region`.

Для оптовых ключей есть отдельные методы:

- `POST /partner-api/keys/products`;
- `POST /partner-api/keys/price`;
- `POST /partner-api/keys/order`.

У ключей остаток может быть приблизительным (`stockDisplay`) и браться из кэша. Окончательное наличие проверяется поставщиком при оформлении заказа.

## Расчет цены

Пример формулы:

```text
sell_price =
  round_up(
    supplier_price_usd × usd_rate
    × (1 + marketplace_fee)
    × (1 + target_margin)
    + fixed_reserve
  )
```

Нужно хранить отдельно:

- исходную цену GPay;
- курс валюты и время его обновления;
- комиссию каждой площадки;
- целевую наценку;
- минимальную прибыль;
- итоговую цену;
- время последней синхронизации.

Перед покупкой у поставщика цену нужно проверить повторно. Для защиты от изменения цены API заказа содержит механизм `disableOrderOnPriceIncrease`.

## Поток заказа

```text
GPay catalog
    ↓ периодическая синхронизация
локальная база и правила наценки
    ↓
карточка на GGsel / другой площадке
    ↓ покупка клиентом
повторная проверка цены, доступности и баланса
    ↓
POST /partner-api/orders
    ↓
POST /partner-api/orders/{pendingOrderId}/confirm
    ↓
контроль статуса и получение результата доставки
    ↓
выдача покупателю / обновление заказа на площадке
```

Для Steam Gift могут потребоваться Steam-профиль покупателя, проверка дружбы с ботом и отдельные действия доставки. Для ключей используется отдельный wholesale flow.

## Защитные механизмы

- Не публиковать товар, если `isAvailable != true`.
- Повторно проверять цену непосредственно перед подтверждением заказа.
- Не подтверждать заказ, если прибыль стала ниже установленного минимума.
- Снимать карточку с продажи при недоступности товара или предупреждении поставщика.
- Ограничивать количество с учетом типа товара и фактического остатка.
- Использовать идемпотентную обработку webhook/заказов, чтобы не купить один товар дважды.
- Вести соответствие `gpay_product_id ↔ marketplace_listing_id`.
- Хранить журнал цен, заказов, ошибок и повторных попыток.
- Никогда не сохранять пароль партнера или JWT в коде; использовать Secrets.

## Важные ограничения

- OpenAPI описывает технические методы, но сам по себе не дает разрешения на перепродажу, копирование изображений или описаний. Это нужно подтвердить в партнерских условиях GPay.
- Нужно проверить правила каждой целевой площадки для Steam Gift, ключей, региональных ограничений и автоматической доставки.
- `currentPartnerPrice` и pricing API возвращают USD; внешняя площадка может использовать другую валюту.
- Цена и доступность меняются, поэтому одноразовый импорт без синхронизации небезопасен.
- Некоторые остатки ключей кэшируются и не гарантируются до создания заказа.
- Следует заранее определить поведение, если клиент заплатил, а поставщик уже изменил цену или потерял остаток.

## Рекомендуемый MVP

Начать с одной связки: **GPay → GGsel**.

1. Импорт только доступных товаров одного типа.
2. Ручное одобрение первой публикации.
3. Автоматическая синхронизация цены и статуса.
4. На первом этапе — ручное подтверждение закупки после продажи.
5. После проверки экономики и возвратов — автоматическое создание и подтверждение заказов.
